# Первый запуск MKS DLC32 V2.2 и DWIN

Для полного интерфейса используйте комплект JD-DGUS2.1-panel5. [Образ MKS](firmware/pending-panel5-20261110/firmware-panel5.bin), пакет
`DWIN_SET` и пульт на ПК обновляются отдельно. При обновлении MKS через OTA
записывайте образ приложения. Конфигурация этой платы `jd_v22_dwin9600.yaml`
содержит параметры осей, UART и соленоида. Сохраните её перед обновлением.

## Связь между компонентами

| Канал | Что передаётся | При потере связи |
| --- | --- | --- |
| Ноутбук ↔ MKS через S24 Ultra, TCP 23 | Команды станка и ответ FluidNC. Пульт читает YAML через HTTP с того же IP | Пульт помечает плату отключённой. Перед повторным рисованием нужны оба угла листа |
| Ноутбук ↔ MKS, TCP 8888, JD-DGUS/2 | Состояние DWIN, проверка ПК, запросы помощнику, предпросмотр листа и разрешение на работу с ПК | Запросы старого сеанса сбрасываются. MKS отзывает разрешение на движение с ПК |
| MKS ↔ DWIN, UART1 | Клавиши и статусы экрана. На заставке показаны этапы, после неё MKS обновляет реальный статус | Пульт показывает, что экран не отвечает. «Меню» на страницах помощника и предпросмотра работает локально |
| MKS → драйверы и реле | Шаги осей и подъём пера. Настройки берутся из активного YAML MKS | При нарушении связи питание можно отключить физически |
| Камера → ноутбук, HTTP | Поток MJPEG и снимки через «Камера и сканирование», по отдельному адресу камеры | Пульт помечает кадр устаревшим. Каналы MKS и DWIN продолжают работать независимо |

Голос для помощника записывается микрофоном ПК. Кнопка на DWIN передаёт
запрос записи, а «Предпросмотр» показывает линии эскиза с ПК.

## Подготовить экран

1. На SD-карте FAT32 с размером кластера 4096 байт должна быть одна рабочая
   папка `DWIN_SET` из пакета [DWIN 800 × 480](../dwin-assistant-20261108/README-RU.md).
2. Вставьте карту в выключенный DWIN, включите экран и дождитесь завершения
   загрузки. Выключите экран, выньте карту и включите снова.
3. При обесточенных устройствах подключите DWIN к MKS. Интерфейс использует
   UART1, 9600 бод, 8N1, без CRC. По фактической схеме платы MKS TX на GPIO23
   идёт к RX экрана, RX на GPIO33 — к TX экрана. Нужна общая земля.

## Проверить связь до движения

1. Оставьте питание моторов и соленоида выключенным. Подключите ПК к точке
   доступа **S24 Ultra** и дождитесь запуска MKS. На DWIN будут видны этапы
   запуска и подключения к пульту.
2. При закрытом пульте запустите `CHECK_SETUP.cmd` и выберите `1`. Проверка читает версию
   MKS, конфигурацию V2.2 и состояние канала DWIN. На JD-DGUS2 отдельно видно,
   отвечает ли физический экран. Успешный ответ на порту 8888 сам по себе
   подтверждает только связь с MKS. Проверка не захватывает управление станком.
3. Если телефон выдал новый IP, при выключенных БП моторов и соленоида
   подключите MKS по USB. Запустите `CHECK_SETUP.cmd`, выберите `2` и подтвердите
   состояние питания. Проверка найдёт CH340, прочитает адрес из ответа именно
   вашей MKS и сохранит его после проверки по сети. При нескольких CH340
   укажите порт явно, например `CHECK_SETUP.cmd --usb COM15`.
4. Если MKS запустила резервную точку доступа `FluidNC`, подключите к ней
   ноутбук и повторите проверку через USB. Адрес в `connection.json` используется
   сразу для обоих соединений. Канал станка — TCP 23, канал экрана — TCP 8888.
5. Запустите `START.cmd`. После подключения проверьте на DWIN переходы
   по меню, «Проверить ПК», запрос помощнику и предпросмотр листа. Версия
   платы читается при подключении. Новые страницы помощника требуют JD-DGUS2.1.

## Первая проверка станка

1. После проверки связи включите питание по штатной схеме. Оставьте запас
   свободного хода. Начните с шага 1 мм и проверьте каждую ось отдельно.
2. Проверьте подъём пера и остановку. Штатный профиль MKS управляет реле
   через GPIO32 LOW, питание соленоида поднимает перо. Сетевой СТОП зависит
   от связи, физическое отключение питания остаётся способом остановки
   при её потере.
3. Заново отметьте верхний левый и нижний правый углы листа. Сначала запустите
   небольшой пробный эскиз. После потери управления проверьте положение
   каретки и задайте оба угла заново перед повторным запуском.

## Если MKS вообще не отвечает

- Если CH340 виден, а версия FluidNC не читается, выключите питание и USB,
  отсоедините разъём DWIN и подключите к MKS только USB. Проверьте запуск платы
  отдельно. Увидеть CH340 в Windows можно даже при неработающем ESP32.
- Если проверка через USB показывает живую MKS и её адрес, а TCP 23
  молчит, сверяйте подключение ноутбука к той же сети и адрес платы. Если
  TCP 23 отвечает, а экран молчит, смотрите отдельно состояние UART DWIN.
- Во время диагностики сохраняйте эскиз и оставляйте силовую часть выключенной.
